# Проверки проекта

Ершов Илья. 5 ноября 2026 года, МСК.

Я проверил код локально на Windows с Python 3.12. Полный набор unit-тестов:
**18 из 18 прошли**. Для тестов не требуются веса модели, vLLM и внешняя сеть.

| Группа | Что проверено | Результат |
|---|---|---|
| Загрузчик | Готовый snapshot используется без создания сетевого клиента | Пройдено |
| Загрузчик | Повреждённый кэш и изменяемая ревизия отклоняются | Пройдено |
| Загрузчик | Snapshot публикуется после проверки хеша, неверный хеш блокирует публикацию | Пройдено |
| Перенаправления | HF token не передаётся другому хосту; переход на HTTP запрещён | Пройдено |
| Пути файлов | Пути за пределами каталога модели отклоняются | Пройдено |
| Конфигурация | Нельзя добавить параметры для снятия авторизации или включения логирования промптов | Пройдено |
| Конфигурация | Проверяются типы и положительные значения лимитов, бюджет без chunked prefill | Пройдено |
| Аудит | В событиях нет содержимого запроса и ответа, включая потоковый ответ и исключение | Пройдено |
| Аудит | Неизвестные события и маршруты не проходят проверку родительского процесса | Пройдено |
| Бенчмарк | Служебный SSE-фрагмент с ролью не считается первым токеном | Пройдено |
| Бенчмарк | При отсутствии usage численные метрики не создаются | Пройдено |

В тестах аудита перехватывается запись в файловый дескриптор: проверяется состав
передаваемых байтов, а не межпроцессное наследование pipe в Linux.
В тестах загрузки HTTP-ответы заменяются небольшими фикстурами.
Ветка блокировки `flock` должна быть отдельно проверена в Linux-контейнере.

Команда повторного запуска:

```bash
python -m unittest discover -s tests -v
```

## Что ещё требует рабочего стенда

На машине подготовки нет Docker, kubectl и установленного Linux через WSL.
Поэтому сборка образов, сверка lock внутри образов, Kustomize build, server-side
dry-run и развёртывание в Kubernetes здесь не выполнялись.
Реальная генерация, авторизация работающего API, проверка живых логов,
повторный запуск с PVC и применение NetworkPolicy тоже требуют проверки в кластере.

Скрипт нагрузки подготовлен, но таблица TTFT, latency и throughput в README пока
не заполнена измерениями. Эти действия и команды для них описаны в README.
